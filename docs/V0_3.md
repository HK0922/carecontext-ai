# CareContext v0.3 — Document Intelligence Studio

**Release type:** open-source research prototype, synthetic test data only.

This version implements the direction chosen for CareContext's next phase: a shared platform with **patient, clinician and researcher perspectives**, **document upload as the primary interaction**, an **optional grounded conversational AI explanation mode**, and an **editorial clinical research interface**. It does **not** accept identifiable medical records in any supported deployment configuration.

## What changed from v0.2

| Capability | v0.2 | v0.3 |
| --- | --- | --- |
| Sources | 3 bundled fictional cases | Bundled cases plus user-supplied fictional PDFs, DOCX, TXT, MD, optional image OCR |
| Main UI | Evidence case-review dashboard | Editorial document intelligence studio, off-white and warm near-black |
| Audiences | General case reviewer | Patient / clinician / researcher wording and suggested questions |
| Conversation | Independent queries | Multi-turn UI; history is passed to optional model and narrow follow-ups inherit prior user terms in local retrieval |
| Evidence | Exact source excerpts from fictional corpus | Source-addressed excerpts of uploaded fictional documents, with filename and page |
| LLM | Optional passage ID selection | Optional structured explanation **with validated citation IDs**; model text is not automatically validated against medical truth |
| Original v0.2 | Main application | Preserved at `/classic` (with original evaluation/literature features) |

## Quick start

1. Use **Python 3.11–3.15** (your Mac 3.14 is supported by the declared dependency versions) and Node.js 22+ if you want to run frontend checks.
2. From the project root, install dependencies in a virtual environment:

```bash
python3.14 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
carecontext serve
```

3. Open `http://127.0.0.1:8000` for the Studio. The original version is at `http://127.0.0.1:8000/classic`.
4. Confirm fictional data, click **Load sample** or choose a synthetic document, then ask a question. Click the citation buttons to inspect the excerpts. A downloadable **fictional laboratory PDF** is provided.
5. Local evidence mode needs no model key. The AI explanation button stays disabled until configured on the **local server**.

For optional AI explanations, export both `OPENAI_API_KEY` and `CARECONTEXT_MODEL` in the server environment. Never paste keys into the UI or commit them. This mode sends selected fictional passages and a small number of conversation turns to the model provider; `store:false` is requested, but third-party retention terms still apply. The model is **not trained** on uploaded documents.

For optional PNG/JPG OCR, install `pip install -e '.[ocr]'` and the **Tesseract** binary locally. OCR is imperfect. Review every extracted value, number, dose, date and name against the original image. Scanned PDFs are *not* OCRed automatically; the upload shows an explicit error.

## API contracts

| Endpoint | Behavior |
| --- | --- |
| `GET /api/studio/config` | Supported file types, size limit, AI availability and synthetic-only boundary |
| `POST /api/studio/ingest?name=sample.pdf` | Raw document bytes (`application/octet-stream`); returns exact text excerpts with `source_id`, `source_name` and `page` |
| `POST /api/studio/answer` | `{question, role, mode, synthetic_ack, snippets, history}`; returns source-bound citations, score trace, status and optional generated explanation |
| `GET /` and `GET /studio` | New v0.3 Studio UI |
| `GET /classic` | Original v0.2 UI (unchanged application logic) |

The request includes the existing `X-CareContext-Session` header acquired from `GET /api/config`. This is a **same-origin anti-CSRF mechanism, not authentication**.

## Engineering design

1. **Document intake**: format allowlist, raw-byte limit (3 MiB), 14-page cap for PDFs, 18,000-character extracted-text cap, 32 passages per document, 4 files per client UI session. DOCX is parsed as XML inside ZIP *without extracting files*, and expansion is capped. Images require an optional local OCR installation.
2. **No app-level upload persistence**: the document request and extracted excerpts are processed in memory. The browser retains them as JavaScript objects until the tab closes or the user chooses Clear session. Browser/network components, the operating system and optional third-party AI providers may have their own logging or memory behavior; this is not a privacy-certified solution.
3. **Source IDs and retrieval**: each document uses a SHA-256 fingerprint and sequential passage IDs. Each passage has the originating filename and page. A lexical BM25-style algorithm ranks excerpts using the question, and the matching terms and scores are exposed for inspection. Ranking is **not** a probability of truth.
4. **Local answer mode**: deliberately avoids AI-generated clinical prose. The result reports matching passages and invites the user to inspect originals.
5. **Optional AI explanation mode**: server-side model is asked to produce a JSON object `{answer, citation_ids, uncertainty, abstain}`. Only IDs within the retrieved excerpts pass the code-level guard. Missing or invalid IDs fail closed. **This does not verify that the natural-language answer entails the citations**; reviewers must inspect it. Model calls are unavailable without server credentials.
6. **Safety boundaries**: requests asking for diagnosis, triage, dosing or treatment advice return an out-of-scope notice. Synthetic-only UI acknowledgement is required. This is not a substitute for authentication, PHI prevention, clinical evaluation, redaction, or human oversight.

## Important limitations

- **Do not upload real prescriptions, identifiable lab reports, real medical records, or actual patient information.** The current application is unapproved for PHI and does not implement access controls, encryption at rest, data retention policies, clinical governance or HIPAA-ready infrastructure.
- A public preview without authentication could be abused to spend API tokens if model mode is enabled; do not expose an API key to a public unauthenticated preview.
- PDF extraction covers embedded text, not scanned PDF OCR; image OCR is optional and dependent on a locally installed binary.
- The app does not verify clinical accuracy or independently check reference ranges, interpretations or evidence completeness.
- Citation IDs show document provenance, **not verified medical correctness**. The optional AI explanation is a clearly labeled draft and can still be wrong.
- This app is not for diagnosis, treatment, emergency assessment or clinical decisions. It has no compliance certification.
- Earlier v0.2 evaluation outcomes concern the fixed synthetic case corpus, not uploaded documents or model-generated explanations.

## Tests and verification

Run:

```bash
python -m pytest
npm run check
npm test
python scripts/check_release.py
```

Unit tests cover text ingestion, a synthetic PDF and DOCX, oversized/invalid files, query boundaries, extraction, lexical evidence matching, citation ID validation, and mocked structured model responses. Local browser layout and interaction testing was run using an **offline API fixture** because the headless browser in the authoring environment could not reach localhost. That fixture tests click/scroll/UI behavior, not the live FastAPI endpoint in a browser. The backend separately passed FastAPI TestClient integration tests. There was **no live model call** or real-user clinical evaluation.
